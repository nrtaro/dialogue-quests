# 演出データ仕様（サイコロ・時計・展開のアニメーション用）

2026-11-04 / Claude Code。

**この文書の役割：** ゲームのサーバーが1手番ごとに画面へ渡すデータの形を決める。アニメーションは別途AIで作成するので、その制作者（人またはAI）は、この文書だけで必要な素材と動きを判断できるようにする。

**決まっていること：** サイコロは画面に見せる。待ち時間の演出は作らない。成功の確率は、行動ごとの目の割り当てで毎回変わる。

**この文書では決めないこと：** 絵柄、色の具体値、音。

## 1. 1手番の流れと、画面に出す順番

1手番のデータは、上から順に再生する「場面（beat）」の列で渡す。画面はこの順に演出し、全部を再生したら入力欄を開く。

| 順 | 場面の種類 | 内容 | 必須 |
|---|---|---|---|
| 1 | `player` | プレイヤーの提案（入力した文） | ○ |
| 2 | `attempt` | 主人公が何に挑戦するか（短い要約）と、その場での一言 | ○ |
| 3 | `dice-bands` | この行動の目の割り当て（どの目なら何が起きるか） | 振る時だけ |
| 4 | `dice-roll` | サイコロの結果（出た目） | 振る時だけ |
| 5 | `outcome` | 結果の段階（大成功・成功・代償つき成功・前進つき失敗） | 振る時だけ |
| 6 | `narration` | 何が起きたかの語り | ○ |
| 7 | `line` | 登場人物の台詞（0〜2個） | |
| 8 | `change` | 持ち物・場所・状態の変化（0〜数個） | |
| 9 | `clock` | 世界の時計の進み | 時計のあるゲーム |
| 10 | `goal` | ゴールの条件の達成・取り消し | |
| 11 | `ending` | 結末（ゲームが終わる時だけ） | |

**サイコロを振らない手番：** 質問、あいさつ、周りを見るだけなど。この場合、3〜5は出さない。

## 2. サイコロと目の割り当て

### 2-1 サイコロ

- 20面のサイコロ1つ（`d20`）。1手番に1回だけ振る。
- 出目はサーバーで決める（乱数）。画面は結果を演出するだけで、画面側で抽選しない。
- 1は必ず「前進つき失敗」、20は必ず「大成功」（毎回、運の余地を残す）。

### 2-2 目の割り当て（行動ごとに毎回変わる）

AIが、行おうとしている物事の中身（状況・持ち物・工夫・危険）から、各段階に何の目を割り当てるかを決める。ルールは次の形を検査し、外れていれば作り直させる。

| 決まり | 内容 |
|---|---|
| 並び | 低い目から「前進つき失敗 → 代償つき成功 → 成功 → 大成功」の順に、すき間なく1〜20を埋める |
| 端 | 1は前進つき失敗、20は大成功に必ず含める |
| 幅 | 成功以上（成功＋大成功）は、最低1目（20のみ）から最大18目まで |
| 省略 | 代償つき成功と成功は、0目（その段階が起きない）でもよい |

例：

| 行動 | 前進つき失敗 | 代償つき成功 | 成功 | 大成功 | 成功以上の確率 |
|---|---|---|---|---|---|
| 流れの速い川を泳いで渡る | 1〜9 | 10〜14 | 15〜19 | 20 | 30％ |
| 浅瀬を探して歩いて渡る | 1〜3 | 4〜5 | 6〜18 | 19〜20 | 75％ |
| 干し肉を分けて獣と仲良くなる | 1〜7 | 8〜11 | 12〜18 | 19〜20 | 45％ |

### 2-3 画面に渡すデータ

```json
{
  "type": "dice-bands",
  "die": "d20",
  "action": "流れの速い川を泳いで渡る",
  "bands": [
    { "tier": "setback", "from": 1,  "to": 9,  "label": "流される",          "reason": "流れが速く、足もけがしている" },
    { "tier": "costly",  "from": 10, "to": 14, "label": "渡れるが体力を失う", "reason": "泳ぎ切れるが無理をする" },
    { "tier": "success", "from": 15, "to": 19, "label": "渡りきる",          "reason": "" },
    { "tier": "great",   "from": 20, "to": 20, "label": "思わぬ発見",        "reason": "" }
  ],
  "chance": { "successOrBetter": 0.30 }
}
```

```json
{ "type": "dice-roll", "die": "d20", "face": 16, "tier": "success", "natural": null }
```

- `natural`：出目が1なら `"one"`、20なら `"twenty"`。それ以外は `null`。特別な演出の目印に使う。
- `label`：各段階で起きることの一言（20字以内）。サイコロの横に帯として見せる想定。
- `reason`：割り当ての理由（30字以内）。詳細を開いた時だけ見せる想定。

### 2-4 アニメーションに必要なもの

| 素材・動き | 内容 |
|---|---|
| 20面サイコロの本体 | 1〜20の面 |
| 目の割り当ての帯 | 1〜20を4色に塗り分けた帯（または円）。段階の色は4種類で固定し、色だけに頼らずアイコンか文字も添える |
| 振る動き | 転がって止まり、出た目が帯のどの段階かを指し示す |
| 段階ごとの止まり方 | 4種類（大成功・成功・代償つき成功・前進つき失敗） |
| 1と20の特別演出 | 2種類 |
| 動きを減らす設定 | 振る動きを省き、出た目と段階だけを表示する版 |

## 3. 結果の段階

| `tier` | 表示名 | 意味 | 演出の方向（案） |
|---|---|---|---|
| `great` | 大成功 | 狙い以上にうまくいき、思わぬ得もある | 最も派手。紙吹雪など |
| `success` | 成功 | 狙いどおり | 明るい決め |
| `costly` | 代償つき成功 | 叶うが、別の困りごとや消耗が出る | 喜び＋小さな「あっ」 |
| `setback` | 前進つき失敗 | 外れるが、手がかりや別の道が開ける | ずっこけ＋「でも…」 |

```json
{ "type": "outcome", "tier": "costly", "title": "渡れた！ でも…" }
```

`title` は12字以内の見出し。AIが書き、ルールが長さを検査する。

## 4. 語り・台詞・挑戦

```json
{ "type": "attempt", "actor": "rio", "summary": "川を泳いで渡る", "line": { "text": "泳ぐの!? ……怖いけど、やってみる！", "emotion": "nervous" } }
{ "type": "narration", "text": "リオは冷たい川に飛び込んだ。流れに押されながらも、必死に腕を動かす。" }
{ "type": "line", "speaker": "rio", "text": "ふう、なんとか渡れたぞ！", "emotion": "relieved" }
```

| 項目 | 上限 | 備考 |
|---|---|---|
| プレイヤーの入力 | 120字 | 超えたら送れない |
| `attempt.summary` | 20字 | |
| `narration.text` | 80〜140字 | |
| `line.text` | 40字 | 1手番に最大2つ |

### 4-1 表情（`emotion`）

全ゲーム共通の一覧から選ぶ。各キャラクターの絵は、この一覧の分だけ用意する。

| `emotion` | 意味 |
|---|---|
| `neutral` | ふつう |
| `happy` | うれしい |
| `excited` | わくわく・張り切り |
| `nervous` | こわい・不安 |
| `surprised` | びっくり |
| `relieved` | ほっとした |
| `sad` | しょんぼり |
| `pained` | 痛い・つらい |
| `thinking` | 考え中・迷い |
| `determined` | 決意 |

演出の方向（案）：入れ替え時の小さな跳ね、汗、きらめき、震えなどの記号表現。

### 4-2 登場人物（`speaker` / `actor`）

各シナリオの定義で、ID・表示名・絵の有無を持つ。勇者の耳元の例：

| ID | 表示名 | 立場 |
|---|---|---|
| `fairy` | あなた（ナビ妖精） | プレイヤー |
| `rio` | リオ | 主人公 |
| `beast` | 親獣 | 祠を守る獣 |
| `cub` | 子獣 | 獣の子 |
| `villager` | 村人・猟師 | AIが登場させうる人物 |
| `healer` | 薬師 | ゴールの相手 |

AIが新しい人物を登場させた場合は `speaker: "extra"` と `name` を付ける。画面は汎用のシルエットで出す。

## 5. 変化（持ち物・場所・状態）

```json
{ "type": "change", "kind": "item-add",    "name": "丸太",            "icon": "generic" }
{ "type": "change", "kind": "item-remove", "name": "干し肉" }
{ "type": "change", "kind": "item-damage", "name": "剣", "note": "柄が削れた" }
{ "type": "change", "kind": "location",    "from": "fork", "to": "riverbank-far", "label": "川の向こう岸" }
{ "type": "change", "kind": "status",      "target": "rio", "key": "injury", "value": "worse", "label": "足のけがが悪化" }
{ "type": "change", "kind": "relation",    "target": "beast", "value": "friendly", "label": "親獣と仲良くなった" }
{ "type": "change", "kind": "fact",        "label": "獣たちが眠っている" }
```

| `kind` | 演出の方向（案） | 素材 |
|---|---|---|
| `item-add` | 持ち物欄に飛び込む | 物のアイコン。シナリオで定義した物は専用、それ以外は汎用（`icon: "generic"`） |
| `item-remove` | 持ち物欄から消える | 同上 |
| `item-damage` | 持ち物にひびの印 | 同上 |
| `location` | 背景の切り替え | 場所ごとの背景。AIが作った新しい場所は、近い既存の背景（`background` で指定）を使う |
| `status` | 人物の横に状態の印 | 状態ごとの小さなアイコン（けが、疲れ、眠り、濡れなど） |
| `relation` | 人物との間にハートや稲妻の印 | 友好・警戒・敵対の3種 |
| `fact` | 「冒険のメモ」に1行追加 | なし（文字のみ） |

**場所の定義（勇者の耳元）：** 森の分かれ道（`fork`）、吊り橋（`bridge`）、川沿いの道（`river`）、川の向こう岸（`riverbank-far`）、祠の入口（`shrine-gate`）、祠（`shrine`）、帰り道（`return`）、村（`village`）。新しい場所は `{ "to": "new", "label": "…", "background": "river" }` の形で、近い背景を指定する。

## 6. 世界の時計

```json
{ "type": "clock", "from": 0.30, "to": 0.42, "phase": "afternoon", "label": "日が傾いてきた" }
```

- `from` / `to`：0（開始）〜1（締切）の割合。画面には数字を出さず、絵で見せる想定。
- `phase`：時間帯の区分（勇者の耳元の例）

| `phase` | 範囲 | 見せ方の例 |
|---|---|---|
| `day` | 0〜0.5 | 青空 |
| `afternoon` | 0.5〜0.75 | 日が傾く |
| `dusk` | 0.75〜0.9 | 夕焼け |
| `sunset` | 0.9〜1 | 日が沈みかけ（警告） |

- `label`：時間の変化を伝える一言（20字以内）。進みがほぼ0の手番では省く。
- **素材：** 時計の表し方はゲームごと。勇者の耳元なら太陽の位置、掃除系なら壁時計など。
- **演出：** 進みの大きさで速さを変える。締切が近い時の警告表現も必要。

## 7. ゴールの条件

画面に常に表示する。手番ごとの変化だけを `goal` で渡す。

```json
{ "type": "goal", "id": "get-herb", "label": "月白草を手に入れる", "status": "done" }
```

| `status` | 意味 | 演出の方向（案） |
|---|---|---|
| `open` | まだ | 空のチェック欄 |
| `done` | 達成 | チェックが入る。印象的に |
| `lost` | 取り消し（例：草を失った） | チェックが外れる |

## 7-A. 障害の解決と、状況の表示（2026-11-04 追加）

障害が解決した手番には、次の場面を出す。

```json
{ "type": "obstacle", "id": "barrier", "label": "台座を守る灯の結界", "status": "cleared" }
```

演出の方向（案）：障害のアイコンが割れる・消える。

画面には、手番の場面とは別に、常に次の3つを表示する（`scene` に含まれる）。

| データ | 内容 | 例 |
|---|---|---|
| `forecast` | 次のゴールの場所までの見込み。`verdict` は ok／tight／hard の3段階 | 「村に帰り着く」：村まで約1時間20分（日没まで約2時間40分）— 間に合いそう |
| `obstacles` | まだ残っている障害 | 祠の前の親子の獣 |
| `hooks` | いまの場面で目につく人や物（指示ではない、材料） | 倒れた丸太・子獣・村への小道 |

**素材：** 見込みの3段階の表示（ok・tight・hard）、障害のアイコン、目につくものの札。

## 8. 結末

```json
{ "type": "ending", "kind": "clear", "title": "日没までに、おかえり。", "text": "（AIが書く締めくくり 80〜140字）", "highlight": "turn-3" }
```

| `kind` | 意味 |
|---|---|
| `clear` | すべての条件を達成 |
| `partial` | 一部の条件を達成して終了 |
| `timeout` | 時計の締切で終了 |
| `score-now` | プレイヤーが「ここまでで採点」 |
| `safety-cap` | 見えない安全上限で、AIが物語を締めくくった |

`highlight`：名場面の手番。結果画面で再生する想定。結果画面（評価・講評・名場面）のデータは別途定める。

## 11. 制作者への注意

- 文字の長さは上限まで入りうる。全角140字の語り、40字の台詞が収まる配置にする。
- 色だけで段階を区別しない（色覚の多様性）。アイコンか文字を必ず添える。
- 1手番の演出の合計は、長すぎない目安（例：通常5秒前後、大成功・1・20で8秒以内）。プレイヤーがタップで早送りできる前提。
- データは追加の種類が増えても壊れないよう、知らない `type` の場面は読み飛ばす作りにする。
