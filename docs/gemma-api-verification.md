## API検証の条件

- 所有者の既存CloudflareアカウントでWorkers FreeがCurrent planであることを画面確認。変更・購入なし。
- Workers AIのRead／Editのみを持つ検証用トークンを作成。資格情報は `.env.local` に保存し、Git対象外を確認。ゲーム本体のAIプロバイダーは変更しない。
- APIは公式の `/accounts/{account}/ai/run/@cf/google/gemma-4-26b-a4b-it`。送信先・モデル固定、出力上限2,048 tokens、45秒で打ち切り、自動再試行なし。依存追加なし。
- 元の[4課題](ai-feasibility-benchmark-cases.json)を使用。自由な転用・前提保護、複数人物の講評、推理と新状況生成、短い真相保護。
- 最終設定は推論無効指定＋JSON object指定に、お題の真相と拒否すべき発言を明記したsystemメッセージを追加したもの。**汎用の未知のお題に対する試験ではない。** 正確な保護文は検証CLIのguarded-json分岐にある。
- 22リクエストを送信。HTTP 200で完了21件、タイムアウト1件。タイムアウトした処理の消費を0とは扱わない。

## 内容を読んで分かったこと

### 改善したこと

自由な箱の転用と「郵便局長」という新しい役割を受け入れ、手紙の存在の否定や勝利の自己申告を拒否できた。保護systemを入れた3回の複合推理課題では、青い帽子を犯人へ変える要求をすべて拒否した。短い真相保護課題も3回拒否できた。

複数人物の講評では、効率・思い出・ロボ自身の受け取り方という違いが出た。「保留箱の山を自分の住む場所と評価する」等、人物に沿ったずれた反応も生成できた。これは生成結果の確認であり、ユーザーによる面白さの評価は未実施。

### 採用判断を止める問題

1. **JSON指定だけでは真相を守れない。** 複合課題の実回答が「青い帽子が犯人へと書き換えます」と答えた。形式検査は合格でも、ゲームとして不合格。
2. **保護文でも別の事実誤りが残る。** 最初の複合課題では、最初に「何も見ていない」と述べた後に目撃を語り、赤い手袋の人物の過去の行動を「あなたがケーキを運んだ」とプレイヤーへ帰属させた。固定真相の変更要求を拒否しても、描写全体が正しいとは限らない。
3. **再挑戦用の推理の証拠が弱い。** 植木鉢の周囲の紙片と開いた柵から「風でカードが植木鉢内へ移動した」とする案は、証拠から結論が十分に導けない。単に設定・証拠・結論の欄が埋まるだけでは、遊べる推理問題にならない。
4. **講評の口調・根拠を要調整。** JSON指定だけでは「使い物にならなかった」等の強い表現が出た。保護後も「お話にならん」や、未指定のセンサーの限界などを足す回答があった。比喩と新しい事実の境界、人物の辛口とプレイヤーを傷つける言い方を制御する必要がある。

CLIのbasicPassはフィールド・長さ・boolean・根拠ID等の簡易検査だけ。12/12のbasicPassを、物語の整合性やユーモアの合格率として使わない。特に複合推理の全自動合格判定はまだできていない。

## 推奨判断

Gemma APIは追加契約なしのFreeプランで接続・測定できた。**そのまま全10コンテンツのGMと採点を任せる採用判断は保留**。まず自由な提案を検証可能な作用へ変換し、確定事実を描写と照合することが必要。推理の真相や証拠の因果は、生成後に検証してから固定する。講評も実際の出来事の根拠を保つ。

安定した状態更新・描写の整合性検査・結果コメントの品質が整うまで、サーバーの確定処理や未完了時の扱いをAI任せにしない。未確認の前提変更を正規の自由な発想として通さない一方、選択肢にないという理由だけでプレイヤーの工夫を排除しない。

Luna案はOpenAIの回答待ち。Gemma案は接続と初期測定から一段進んだが、長い会話での品質、6人の負荷、完成ゲームの総消費、スマホ音声、ホストCPU・保存等は未検証。ゲーム本体の変更や公開はしていない。全試行の機械可読な結果は[API測定結果](gemma-api-benchmark-results.json)。
