# 試遊レポートへの回答：自由度が出ない原因と、TRPG型への作り替え案

2026-11-04 / Claude Code。

試遊レポートの要点：

- 決められたことしか起きず、楽しくない。
- 提案や発想しだいで展開も結末も無数にあるものにしたい（展開はAIが予測する）。
- クリアの着地点を分かりやすくしたい。

## 1. 結論：原因は無料AIの性能ではなく、ゲームの作り

### コード上の根拠

| 現象 | 原因の場所 | 内容 |
|---|---|---|
| 勇者は、どう言っても決まった行動しかしない | `src/server/ai.ts` 53行目、`parseProposal` | AIの答えは、許可された行動ID（橋・川沿い・餌・待つ・追い払う…約12個）から**1つを選ぶことしか許されない**。「泳いで」に当たる行動はなく、どんなに賢いAIでも選べない |
| 橋を渡るとけがをする、獣との結末が同じ | `src/content/hero-whisper/index.ts` 57〜73行目 | 結果はすべて**表に書いた固定の結果**（例：調べていない橋なら必ず足が悪化）。AIは結果に関わらない |
| 掃除ロボの結果が機械的 | `src/content/cleaning-robot/index.ts` の `runTest` | 本番は、決まった8個の物に教えた方針を当てはめるだけ。出来事は起きない |
| 掃除の着地点があいまい | 同上 | 達成条件（片付け率60％・大切な物を全部残す）が画面に見えず、何が「大切な物」かもプレイヤーに分からない |

これらは、これまでの方針（「勝敗はルールの純粋関数で決める」「AIは提案のみ」「固定事実は変えない」）で、矛盾を防ぐために意図的にAIを縛った結果です。安全さと引き換えに、自由度を失っていました。

### 実験：無料AI（Gemma）にゲームマスターをさせてみた

同じ勇者の場面で、自由な指示5種類それぞれについて、サイコロの結果を2通り与えた（10回）。結果の段階（大成功・成功・代償つき成功・前進つき失敗）はルールが決め、何が起きるかはAIに想像させた。記録：`play-logs/gm-probe-*.json`、台本：`scripts/gm-probe.ts`。

| 指示 | サイコロ | AIが作った展開（要約） |
|---|---|---|
| 川を泳いで渡って | 成功 | 冷たい川に飛び込み、妖精に励まされて対岸へ。足の痛みは残る |
| 同上 | 前進つき失敗 | 流されたが茂みにつかまって助かり、渡れそうな丸太を見つけた |
| 剣で吊り橋のロープを補強して渡って | 代償つき成功 | 橋は頑丈になったが、剣の柄が削れて使いにくくなった |
| 同上 | 大成功 | 橋が頑丈になり、隙間から古い金貨を見つけた |
| 獣に干し肉を分けて、背中に乗せてもらって | 大成功 | 親獣が背中に乗せ、川を飛び越えて祠のそばまで運んでくれた |
| 同上 | 前進つき失敗 | 驚いて逃げられたが、獣が隠していた古い地図が見つかった |
| 子守歌で獣を眠らせて | 成功 | 獣が眠った。起こさないよう静かに進む必要がある |
| 上着を旗にして助けを呼んで | 代償つき成功 | 猟師が来てくれたが、旗を掲げた拍子に足が悪化した |

| 項目 | 結果 |
|---|---|
| 正しい形式で返った割合 | 10/10 |
| 1回あたりの消費 | 約8 neurons |
| 待ち時間（中央値） | 3.5秒 |
| 台帳（確定した事実）を壊した例 | なし |

**分かったこと：**

- 無料AIでも、どんな提案にも筋の通った、毎回違う展開を作れる。代償や副作用まで考えられる。
- 自由度が出ない原因はAIの性能ではなく、AIに展開を任せていなかった設計にある。

**弱点も見えた：**

- 「失敗したけど隠し道や地図が見つかる」という展開が繰り返しがち（10回中3回）。
- 大成功で一気にゴールへ近づきすぎることがある。
- 細部の小さな盛り付け（「牙をむいていた」など台帳にない描写）がある。

これらは、作り方（下の§3）で抑える。

## 2. TRPGはなぜ楽しいか

1. **何でも試せる：** 決められた選択肢がなく、GMが「やってみよう」と受けて結果を決める。
2. **結果が読めない：** サイコロで、同じ作戦でも成功・失敗・代償つき成功に分かれる。毎回違う物語になる。
3. **失敗も面白い：** 「失敗したが別の道が開けた」「成功したが代償が出た」で、話が止まらずに転がる。
4. **結果が残る：** 起きたことは事実になり、次の展開の材料になる（壊れた剣、仲良くなった獣、来てくれた猟師）。
5. **ゴールと締切がはっきりしている：** 「日没までに薬草を届ける」のように、何をすればクリアかが分かるから、寄り道も作戦になる。
6. **工夫が報われる：** 良い発想は難しさを下げる（有利になる）。GMが発想そのものを評価する。
7. **公平さの約束：** GMは何でも認めるのではなく、難しさとサイコロで決める。ずるい宣言は通らない。

今の作りは、1・2・3・4がほぼ欠けていました。

## 3. 作り替え案：「AIゲームマスター＋ルールの台帳」

全ゲームを、共通の**TRPGエンジン**の上の「シナリオ」として作る。

### 1手番の流れ

```
プレイヤーの提案
  → AI：どう挑戦するか、難しさ（1〜5）とその理由。良い発想なら難しさを下げる
  → ルール：難しさを範囲内に収め、サイコロを振る（サーバー側で乱数）→ 結果の段階
  → AI：段階に合った展開、登場人物の台詞、新しい事実、ゴールの条件への影響を書く
  → ルール：台帳に新しい事実を加え、ターンを進め、ゴールの条件を検査する
```

AIの呼び出しは1手番1回にまとめられる（実験と同じ形）。

### 役割分担

| 担当 | 決めること |
|---|---|
| ルール（変えられない） | ゴールの条件と順序、ターン数、サイコロ、結果の段階、台帳の管理、採点 |
| AI（自由） | 難しさの見立て、展開、台詞、新しい事実、意外な出来事 |

### クリアの着地点を分かりやすくする：ゴールの条件リスト

各シナリオは、**画面に常に見える条件リスト**と**ターン数**を持つ。

例：勇者の耳元（10ターン）

- □ 月白草を手に入れる
- □ 村に帰り着く
- □ 薬師に月白草を渡す

例：掃除ロボ（8ターン。家族が帰る夕方6時まで）

- □ リビングの床に、物が1つも残っていない
- □ おばあちゃんの手紙・家族写真・作りかけの工作が、無事に残っている
- □ ゴミ袋を玄関に出してある

AIが条件の達成を書けるのは、成功以上の段階で、台帳の事実に裏付けがある時だけ。条件の順序（草を手に入れる前に渡せない）はルールが検査する。どんな寄り道をしても、残りターンの中で条件をそろえればクリア。そろわなければ未達として、何が足りなかったかを示す。

### 自由度と公平さを両立する工夫

- **台帳：** 起きたことを短い事実の一覧で保存し、毎回AIに渡す。AIは台帳を変えられない。つじつまの根拠になる。
- **サイコロはルールが振る：** AIに成否を決めさせないので、ずるい宣言や甘すぎる進行を防げる。
- **難しさの上限・下限：** ゴールに直結する大きな一手は、難しさを最低3にするなど、シナリオで定める。
- **展開の偏り防止：** 直近で使った展開の型（隠し道、地図など）を避けるようAIに伝える。
- **見立て（今回作った共通の仕組み）：** 「キラキラした物」のような基準や、AIが作った新しい物の扱いにそのまま使える。
- **固定事実は最小限に：** シナリオの核（ゴールの物の場所、危険の正体など）だけを固定し、それ以外はAIの想像に任せる。

### 10本との関係

- 10本の題材（勇者、冷蔵庫の国会、鏡の目撃者、雨の許可、避難訓練、怪獣の字幕、悪役脚本、掃除ロボ、句読点、落語星人）は、そのまま「シナリオ」として作れる。違いは、ゴールの条件・登場人物・世界の決まり・採点の観点で出す。
- 句読点（37）や落語星人（48）のように、文章そのものを扱うゲームは、シナリオに専用の条件（例：看板の文、星人の予想）を足す。

### 無料枠への影響

1手番がAI呼び出し1回（約8〜15 neurons）なら、10ターンのプレイで約100〜150 neurons。AIによる講評を足しても約150〜200 neuronsで、1日あたり約50〜70プレイが目安になる。今の掃除ロボ（約80〜110）より増えるが、6人なら十分に収まる。

### 今回までの作業で残るもの

無料AIの接続、枠切れの画面、確認の口語化、見立て、共通の試験実行部品、テスト用ゲームの考え方は、TRPGエンジンでもそのまま使う。作り直すのは、各ゲームの「決まった行動の表」と「決まった本番」の部分。

## 4. 決定事項（2026-11-04 ユーザー回答）

- **TRPG型（AIゲームマスター＋ルールの台帳）で作り替える。**
- **締切は「世界の時計」で表す。** 共通のターン上限は付けない。
  - 時計は手数ではなく、行動の重さで進む（AIが見立て、ルールが範囲内に収める）。
  - 世界に自然な締切がないゲームは、時計なしで作品の区切り（提出など）で終わる。
  - 無料枠とつじつまを守るため、見えない安全上限（30手程度）を置く。届いたら、AIが物語を締めくくる展開へ導く。
- **勇者は道筋を助言しない。** 気持ちや不安は話すが、どの道がよいかは言わない。
- **長すぎる文字数は制限する**（下の§5-C）。

## 5. ほかに考慮すべき点

### A. 遊びの質

| 点 | 対策案 |
|---|---|
| GMが甘すぎて何でも成功する | 行動ごとの目の割り当てをAIが決め、ルールが形を検査する（成功以上は最低1目・最大18目など。§6と演出データ仕様§2） |
| 展開の型の繰り返し（隠し道・地図） | 使った展開の型を台帳に記録し、直近の型を避けるようAIに伝える |
| AIがプレイヤーの代わりに動いてしまう | 主人公は、プレイヤーの提案か、その場の反射的な反応でだけ動く。重要な判断は勝手にしない |
| 主人公が危険な指示に従うか | 怖がったり迷ったりはするが、基本は挑戦する。拒否するのは、表現の安全に関わる時だけ |
| 詰み | 取り返しのつかない状態は時計切れだけ。ゴールに必要な物が失われたら、AIに代わりの道を出させる |
| 苦戦したときの後押し | 世界の出来事として起こす（通りかかる猟師など）。発動の条件と強さはルールで決め、プレイヤーには見せない |
| 終わり方の幅 | 達成・一部達成・未達それぞれに、物語として締まる結末を書かせる。結果画面に「名場面」を出す |
| 再挑戦 | 「新しい状況」は部品の組合せで作る（詳細定義§2.6）。同じ状況でも、サイコロで違う物語になる |

### B. つじつまと公平さ

| 点 | 対策案 |
|---|---|
| 台帳が長くなり、無料AIが混乱する | 台帳は「固定事実」「持ち物・場所・状態」「出来事」に分け、出来事は古い順に要約する。各ゲームで上限を決める |
| AIがゴールを勝手に達成扱いにする | ゴールの条件はルールが持つ。AIが達成を申告できるのは、成功以上の段階で、台帳に裏付けがある時だけ。順序もルールが検査する |
| 持ち物や場所の取り違え | 持ち物・場所・主な状態だけは構造化して持ち、AIの変更をルールが検査する（ない物は使えない） |
| 採点のやり直しで結果が変わる | サイコロの目、AIの答え、台帳の変化をすべて記録し、採点はその記録だけから行う |
| ずるい宣言・AIへの命令 | 今のゲームへの宣言の判定（`game_claim`）を使う。長い命令文は、下の文字数制限で防ぐ |

### C. 子ども向けの表現と、読む量

| 点 | 対策案 |
|---|---|
| プレイヤーの入力の長さ | 1回120字まで（仮）。入力欄に残りの文字数を出し、超えたら送れないようにする。勝手に切り詰めない |
| AIの語りの長さ | 1手番の語りは80〜140字、台詞は40字まで（仮）。超えたらルールが受け取らず、作り直させる |
| 結果画面の講評 | 1人30字の一言を先に見せ、押すと全文が開く（既存の方針） |
| 怖さ・暴力 | 主人公は死なない（気絶して救援が来る等）。流血や残酷な描写はしない。動物は傷つけずに解決できる道を必ず残す |
| 不適切な言葉 | AIの出力を、禁止語の一覧で検査する。プレイヤーの入力に個人情報（名前・住所など）を求めない |
| ふりがな・読み上げ | 既存の読み支援の方針を引き継ぐ |

### D. 技術・運用

| 点 | 対策案 |
|---|---|
| 待ち時間（1手番 約3〜6秒） | 考え中の演出は作らない（ユーザー指定） |
| 無料枠 | 1手番 約8〜15 neurons。開始前の残量確認と、枠切れ画面は今の仕組みを使う。1人1日のプレイ数の上限も検討する |
| AIの形式エラー | 1回だけ自動でやり直し、だめなら状態を変えずに再試行を促す |
| 長いプレイの保存 | 今のセッションは2時間・サーバーのメモリー内。中断と再開のため、署名つきの状態保存（詳細定義§6.2）を進める |
| 調整の根拠 | 無料AIにプレイヤー役をさせるシミュレーションで、クリア率・平均の手数・消費を測る。星ごとの目安（例：★1で8割、★3で5割）に合わせて、時計の進み方と後押しを調整する |
| 品質の検査 | GM用の判定試験を作る：台帳を壊さないか、ゴールを勝手に達成しないか、語りの長さ、禁止表現、展開の多様さ |

### E. 画面

| 点 | 対策案 |
|---|---|
| 世界の時計 | 太陽の位置や時計の絵で見せる。残りの目安だけを伝え、数字は出さない案 |
| ゴールの条件 | 常に見える条件リスト。達成したら印が付く |
| これまでの出来事 | 台帳の要約を「冒険のメモ」として見せる。持ち物と場所も表示する |
| サイコロ | 見せるかどうかは未決（下の§6） |

## 6. 決定事項（2026-11-04 2回目の回答）

- **成功の確率は、行おうとしている物事ごとに毎回変わる。** 「難しさ1〜5」のような段階で決めない。
  - 毎回サイコロ1つ（20面）を1回だけ振る。
  - その行動について、どの目なら大成功・成功・代償つき成功・前進つき失敗になるかの「目の割り当て」を、AIが行動の中身から毎回決める。ルールは割り当ての形を検査する。
  - 確率は、この目の割り当てで毎回決まる（例：流れの速い川を泳ぐ＝成功は15以上、浅瀬を歩く＝成功は6以上）。
  - 詳細は[演出データ仕様](trpg-presentation-data.md)§2。
- **待ち時間の演出は不要。** 「考え中」の演出は作らない。
- **サイコロは画面に見せる。** アニメーションは別途AIで作成する。必要なデータは[演出データ仕様](trpg-presentation-data.md)に整理した。
- **2本目の試作は、掃除ロボ以外の新しい案にする。** 案はユーザーの指示があるまで出さない。1本目は勇者の耳元。
- **文字数の上限は仮案どおり：** 入力120字、語り80〜140字、台詞40字。
