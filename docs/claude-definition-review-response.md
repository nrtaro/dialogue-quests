# AIデア放題！ Claude定義書レビューへの対応

2026-11-03。ローカルのClaude Codeに定義書本文のみを渡して実際にレビューを実行。ツールとカスタマイズを無効化し、セッション非保存で取得した。最初の呼び出しは応答が返らず中断し、呼び出し方法と実行環境を変えた再試行で取得した。原文はclaude-definition-review.mdに保存。定義書は原文レビュー後に§11を補足したため、補足後の再レビューを受けたとは称さない。アプリのコードは変更していない。

## 総評

Claudeは、方針の大きな矛盾はなく、確定・提案・保留の区別も明確と評価。一方、自由な手段と状態変化の接続、子どもの自由入力の扱い等を実装計画前に詰めるよう指摘した。

## 指摘の扱い

| 指摘 | こちらの判断・対応 |
|---|---|
| 1. 状況的な実行可能性と状態変化の接続が未定義 | 重要。固定事実・可変状態・補完可能範囲を分ける案を§11.1へ追加。ただしClaude案の「既存の可変要素だけへ限定」をそのまま採用すると自由度を損ねるため、既存解法へ閉じない拡張を検証する。新しい事実の補完範囲は保留 |
| 2. 子どもの自由入力・音声と講評の扱い | 本人を揶揄しない、平易な案内、自由入力の出力範囲・保存の扱いを共通設計へ含める案を§11.3へ追加。最低年齢や保護者向け表示は未決。全年齢志向を勝手に変更しない |
| 3. 即採点と高ランク、採点の揺れ | 根拠のない高評価は防ぐ。一方、短い手数や自分で終了したことだけではランク上限を設けない案。各項目の根拠、評価材料不足、段階基準、再採点の揺れの確認を§11.2へ追加。配点・閾値は保留 |
| 4. 3〜5分に収まりにくい案がある | 短い初期素材・試験の要約・実測を§11.4へ追加。自由入力を穴埋めや選択肢だけへ制限する案としては採用しない |
| 5. 音声の文字修正が子どもの負担になる | 確認後送信の方針を維持し、録り直しと大きな文字を§11.3へ追加。重要な入力をAIが無断で書き換える形にはしない |
| 6. 10本の専用表示・状態・AI処理の負担 | 部品の共通化と、既存勇者＋異なる型の新規1本で検証する案を具体化。31を第一候補として§11.4へ記載。制作順は技術的な提案で、ユーザーに設計作業を返す必須質問にはしない |

## 残る判断と限界

新しい物・事実を補ってよい範囲、対象年齢に応じた読み支援・表示、配点とランク体系、APIモデル・使用上限、保存・履歴・予算・公開規模などは保留。ユーザーが採用した大枠と混ぜず、次の仕様具体化・実装計画で扱う。

このレビューは文書の整合性と企画の実現性の検討であり、実装検証・実機確認・費用の実測・名称の使用可否の確認ではない。特に自由度の実現可能性と採点の納得感は、まだ試作による検証が必要。
