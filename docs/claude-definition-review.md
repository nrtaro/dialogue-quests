# 「AIデア放題！」ゲーム内容定義書 レビュー

**結論：** 方針の大きな矛盾はありません。確定・提案・保留の区別も明確で、このまま次の段階へ進める品質です。ただし、**「自由な手段」を確定可能な状態変化へつなぐ仕組み**と、**子どもの自由入力に対する安全の扱い**の2点は、試作の前に方針を決めておく必要があります。

以下は重要度順の指摘6件です。配点、閾値、星の値、ランク名などの未決数値は、保留として妥当なため指摘に含めていません。

---

## 指摘1：「状況的に不可能でない」を誰がどう判定し、状態へ反映するか

- **該当節：** §4、§8（現行基盤・既存AGENTS.md）
- **問題：**
  - §4の確定方針「状況的に不可能でない展開は可能にする」と、§8の原則「既定事実・資源・勝敗をサーバーで検証する」は両立できます。しかし、その接続方式が未定義です。
  - サーバーは、状態に定義済みの要素しか検証できません。たとえば「マントを帆にする」のような未定義の手段が出たとき、次のどれになるかが決まっていません。
    - 新しい状態として確定する
    - 演出だけで終わる
    - 拒否する
  - この判断がAI任せになると、同じ案が回によって通ったり通らなかったりします。その結果、§6の「再挑戦による上達」も成り立ちにくくなります。
- **修正案：**
  - コンテンツ定義の必須項目として、次の3層を設けます。
    1. **固定層：** 真相、確定済み証拠、勝敗条件など、変更不可のもの
    2. **可変層：** サーバーが管理する資源、位置、関係値、成果物
    3. **補完可能層：** AIが世界の法則の範囲で新しく足してよい物や性質と、その上限
  - AIからの提案は「却下（世界内の理由を付ける）」「演出のみ」「状態変化」の3種類に分類して返させます。サーバーは、状態変化の結果が固定層と勝敗条件に反しないかだけを検証します。
  - 自由な案が勝敗へ影響する経路は、「既存の可変要素の値が変わる」形に限定すると、検証可能性を保ちやすくなります。
- **ユーザー判断：** **要**。AIが新しい物や事実を状態として足してよい範囲は、遊びの手触りを大きく左右します。原則として「広め」と「狭め」のどちらにするかを決めてください。各コンテンツの細部は後で調整できます。

## 指摘2：子どもの自由入力・音声を前提にした安全方針が未定義

- **該当節：** §1（子どもから大人まで【確定】）、§7、§9（全年齢は「案」）
- **問題：**
  - §9は全年齢を、主に表現の幅の問題として扱っています。しかし、自由入力のAIゲームで重要なのは**入力側**です。具体的には次の扱いが定義書のどこにもありません。
    - 不適切な語や話題
    - 名前、学校、住所などの個人情報
    - 悩みや危険に関わる発言
  - 音声を外部へ送る点について、子どもや保護者向けの説明をどうするかも未定義です。
  - ユーモアのある講評が、子どもを笑いものにする方向へ傾く懸念もあります。
- **修正案：**
  - 共通基盤の項目に、次の安全層を加えます。
    - 入出力の安全確認
    - 不適切な入力への穏やかな世界内の返答（説教ではなく話をそらす）
    - 個人情報を入れないよう促す短い案内
    - 該当する発言をゲーム側で保存しない方針
  - 講評の原則として「プレイと作品を面白がり、本人を揶揄しない」を§6に明記します。
  - ホラーやブラックユーモアの幅は、現状どおり保留で問題ありません。
- **ユーザー判断：** **要**。想定する最低年齢（例：小学校中学年から）と、保護者向けの注意表示を置くかどうかを決めてください。

## 指摘3：「ここまでで採点」と「未達でも高ランク」の組み合わせ

- **該当節：** §3-4、§6
- **問題：**
  - 次の2つはどちらも確定方針です。
    - いつでも「ここまでで採点」を選べる
    - 未達でも発想や過程で高ランクを狙える
  - この2つを組み合わせると、「1手目に面白い案を出して即採点」が最も効率の良い遊び方になる恐れがあります。
  - また、LLMの採点はぶれやすい性質があります。同じプレイでランクが変わると、上達の実感が損なわれます。
- **修正案：**
  - 結果に「達成／未達／途中採点」の区別を明示します。
  - 評価項目ごとに「根拠となった出来事」を記録から引用させ、根拠のない項目は評価しないようにします（§6の「実際の出来事を取り上げる」を採点の必須条件にする形です）。
  - 項目ごとに段階の説明（どの水準ならどの評価か）を課題ごとに用意します。
  - 試遊では、同じ記録を複数回採点してばらつきを確認します。
- **ユーザー判断：** **要**。途中採点で到達できるランクに上限を設けるかどうかを決めてください。最高ランクの要件そのものは保留のままで構いません。

## 指摘4：3〜5分に収まりにくい構造のコンテンツがある

- **該当節：** §1、§5（13、30、31、48、07）
- **問題：**
  - 13（規則作成→運用→修正）と31（教える→未見の部屋でテスト）は、手順そのものが多段階です。30と48は成果物を書く必要があります。
  - AIの応答待ち、音声の確認、子どもの入力速度を考えると、5分で実際にできるのは数往復程度と見込まれます。
  - 長短を許容する方針自体は妥当です。ただ、これらが常に倍以上かかる場合、「基本3〜5分」という作品全体の約束とずれます。
- **修正案：**
  - 各コンテンツに「最短で完走できる手数」の目標を設けます。
  - 白紙から書かせず、次のような足場を用意します。
    - 書き出しの選択肢
    - 下書きの穴埋め
    - 最初の規則の例
  - 13や31のテストや運用は、自動で短く再生して結果だけを見せます。
  - 試遊で時間が超過する場合は、分量を削る前に段階を減らします。
- **ユーザー判断：** **不要**。試遊で調整できる範囲です。

## 指摘5：音声の「確認・修正」段階が子どもの負担になりうる

- **該当節：** §7、§4（子どもの短い表現を受け止める）
- **問題：**
  - 「文字起こし→確認・修正→送信」は確定方針です。しかし、読み書きが苦手な子ほど音声に頼るため、誤った認識結果を文字で直すことが難しくなります。
  - 子どもの声は認識精度も下がりがちです。確認の段階が新たな壁になると、音声入力を用意した意味が薄れます。
- **修正案：**
  - 確認画面は大きな文字で表示し、主な操作を「そのまま送る」「もう一度話す」の2つにします。文字での修正は補助に回します。
  - ゲーム側のAIには、聞き間違いらしき語を文脈で解釈する余地を持たせます。大きく影響する場合は§4の「短い確認」を返す形にし、多少の誤認識なら確認なしで遊べるようにします。
  - 確定方針の確認段階はそのまま維持し、軽くするだけです。
- **ユーザー判断：** **不要**。ふりがなを付けるかどうかは、指摘2の対象年齢が決まった後で判断すれば十分です。

## 指摘6：10本それぞれに専用の表示と仕組みが必要で、実装負荷が大きい

- **該当節：** §5、§8、§10
- **問題：**
  - 10本のほとんどが、会話欄とは別の中心表示や仕組みを必要とします。
    - 証拠盤（07）
    - 規則エディタと運用試験（13）
    - 配置図（19）
    - 字幕欄（25）
    - 脚本（30）
    - テスト場面（31）
    - 看板文の編集（37）
    - 入力前に予想を固定する仕組み（48）
  - これに、複数のAIの役割（人物・世界・採点、秘密を知る役と知らない役）が加わります。1手あたりのAI呼び出し回数と費用も膨らみます。
  - §10の「勇者の耳元＋新規1本で検証」という方針は妥当です。ただし、2本目の選び方次第で、残り8本への展開のしやすさが大きく変わります。
- **修正案：**
  - 10本を、遊びの型で3〜4種類に分類します。
    - **会話で状況を動かす：** 勇者、01、25
    - **調べて答えを出す：** 07
    - **作って試す：** 13、30、31、48
    - **配置・編集する：** 19、37
  - 中心表示と状態管理を型ごとに共通化します。
  - 2本目は勇者の耳元と**別の型**から選びます。たとえば31は「作って試す」型の検証になり、教える・テストする・採点するの流れを一度に確かめられます。
  - 1手あたりのAI呼び出し回数の目安も、試作段階で測ります。
- **ユーザー判断：** **要**。検証用の2本目にどのコンテンツを選ぶかを決めてください。

## 総評

確定方針、設計提案、保留が明確に分けられており、現行デモとの差、自由度の未達成、採点の公平性が未検証であることも自ら明記されています。初版としてとても誠実で、扱いやすい定義書です。

- **矛盾について：** 方針同士の正面衝突はありません。たとえば「時間では強制終了しない」と勇者の耳元の「日没」は、後者がゲーム内の時間なので両立します。
- **最大の課題：** 確定方針の中心である「自由な手段」を、サーバーで検証できる状態変化へ結び付ける方式が、まだ言葉の上の原則にとどまっていることです（指摘1）。ここが決まると、指摘3（採点の安定）と指摘6（型ごとの共通化）も具体化しやすくなります。
- **全年齢について：** 表現の幅は保留で問題ありません。ただ、入力側の安全は基盤の一部として、早めに定義しておくべきです（指摘2）。
- **10本の規模について：** 本数を削る必要はないと考えます。型ごとに共通化し、異なる型の2本で先に検証すれば、現実的な規模に収まります。

ユーザー判断が必要な点は4つです。

1. AIが新しい事実を足してよい範囲（指摘1）
2. 対象年齢と保護者向けの表示（指摘2）
3. 途中採点のランク上限（指摘3）
4. 検証用2本目の選定（指摘6）

これらが決まれば、試作へ進めます。
