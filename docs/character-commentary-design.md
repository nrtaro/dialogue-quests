# 複数人物の講評設計

## ユーザーが重視すること

- 何が起きたかの流れをしっかり汲み取る。
- 複数の人物が、それぞれ別の観点から、それぞれの人格に沿ってコメントする。
- 人物らしさとユーモアを両立し、講評そのものを楽しめるようにする。

## 講評に使う記録の設計案

各人が同じ確定済みプレイの記録を共有し、目的、初期状況、プレイヤーの意図・提案、実際の反応と状態変化、途中の失敗、修正、最終結果を追えるようにする。意図と実行、仮説と事実、冗談と実際の出来事を区別する。短い記録へ要約する場合も、評価を変える修正や因果を落とさない。

全員が全経緯を再説明する必要はない。それぞれの観点で重要な場面を取り上げ、前後の変化が分かるコメントにする。「一度失敗した」ことと「失敗して工夫を変えた」ことを同じ扱いにしない。プレイヤー本人を揶揄せず、作戦や出来事を面白がる。

## 人物ごとの差の設計案

人物には、世界内での立場、重視する価値、注目する評価観点、性格、口調、語彙、冗談の出し方、知ってよい情報を定義する。例えば実用性を気にする現場の人物、相手の気持ちを大切にする当事者、意外な発想に喜ぶ変わり者など。毎回同じ三役を全ゲームへ強制せず、コンテンツの人物として自然な役割を選ぶ。

講評は「今回のどの出来事か」「それをどう受け取ったか」「人物らしいひと言」を含む案。全員に同じ書式の長文を強制せず、具体的な根拠と読みやすさを保つ。笑いを機械的に一文ずつ追加せず、その人の価値観から自然に生まれるコメントを狙う。

同じ出来事を、実用面では褒めつつ気持ちの面では疑問視するなど、見方の違いは許容する。ただし、起きた事実そのものを人物ごとに変えない。人物の意見の食い違いと、得点計算や達成判定の矛盾は区別する。複数講評を複数独立採点にするかは未決。

人数は3人を比較用の案とするが、採用済みではない。人物同士の短い掛け合いも候補であり、まだ必須としない。コメントはまず短く読めるようにし、詳細の開き方や表示順は結果画面の設計で具体化する。

## 架空のプレイと講評例

「善意100％の掃除ロボ」の説明用の例。実際のプレイログではなく、人物も仮案。

流れ：ロボは床の物を全部捨てようとした。プレイヤーが「迷ったら保留」と教えると片付けが止まった。そこで「通り道を先に空ける」「手紙は専用の箱へ」「残りは保留箱へ」と教え直した。最後は手紙を守って通り道を確保したが、保留箱には物が多く残った。

- **古い掃除機／実用性と改善を見る：** 「最初の『迷ったら保留』では、床の物が動かなかったな。だが、通り道を先に空けると教え直したのはよかった。これでわしも通れる。保留箱の中は……次の担当に引き継ごう。」
- **持ち主のぬいぐるみ／大切な物への配慮を見る：** 「手紙を専用の箱に残してくれて、ほっとしたよ。最初は何でも捨てそうだったからね。この家では、紙切れより思い出のほうが場所を取るんだ。」
- **掃除ロボ本人／教わった仕組みと勘違いを見る：** 「『迷ったら保留』だけのときは、全部を保留すればよいと思っていました。順番と手紙の置き場所を教えてもらって、動けるようになりました！ まだ保留箱はいっぱいです。次は、箱が迷わない置き場所を教えてください。」

笑いの強さ、長さ、人物の魅力は引き続き調整する。ユーモアを優先して、実際には起きていない騒動をプレイ履歴へ追加しない。比喩や仮定を使う場合も、実際の出来事と区別できるようにする。

## 検証する点

実際の流れに対応しているか、修正を読み落としていないか、人物ごとの注目点が異なるか、口調だけの差になっていないか、出来事から自然に笑いが生まれているか、子どもも読めるか、総合ランクと説明が矛盾していないかを確認する。同じログを使って講評例を比較し、内容の根拠と人物表現を別々に評価する。プロンプトの記載だけで品質を保証したとは扱わない。
