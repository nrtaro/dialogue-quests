## 現在の基準

仮題、初期10種類、自由選択中心、基本3〜5分、⑤くらいの自由度、文字・確認後送信の音声入力、内容別の終了、未達でも高ランクを狙えること、面白い展開の記録と結果画面での任意保存、難度によらず子どもが状況を理解できること、低難度の一人プレイと大人の発想の広がり、複数人物の経緯を踏まえた個性的・ユーモラスな講評は確認済み。

当初の引継ぎ資料に初期利用者約5人が記載されていた。一般公開へ変更されたとは扱わず、少人数で検証する前提を引き継ぐ。公開・課金・mainマージは独立した判断。後続の実際の公開方針や予算は必要な段階で確認する。音声入力の採用と基本時間3〜5分は、当初デモの範囲から後続回答で更新された事項。

## まず確認する2つの体験判断

1. **同じコンテンツを選び直したときの変化。** 同じ初期状況で作戦を変えること、新しい人物の事情・道具・事件などで遊ぶこと、両方を選ぶことの優先度。新しい状況もプレイ開始後の真相変更とは分ける。変化は無制限の毎回生成でなく、検証済みのお題と条件の組合せで実現する案も比較する。
2. **言葉による指示と直接操作の関係。** 文字・音声入力は採用済み。その上で、証拠カードを選ぶ、規則を直接編集する、配置図の対象を選ぶ等の補助をどの程度遊びの中心にするか。スマホや音声でも使える共通性と、ゲームごとの触り心地の違いに影響する。

回答：同条件・新しい状況の両方を選べる形を採用。新しい状況では事情を毎回変え、設定と結末の筋が通るように用意する。操作は言葉の指示のみと指定。直接操作を組み合わせる推薦案は採用しない。証拠・地図・規則等は見るための表示として設計し、変更は文字・音声の指示で行う。次はゲームごとの難度表示と、各ゲーム内の難度選択を区別して確認する。

## 分析とヒアリングを循環させる

難度の追加回答はA方式。ゲームごとに星の難度を設定し、各ゲーム内の難度選択は初期に含めない。具体値は設計・試遊で決める。次は少人数試遊時の全体費用の許容範囲を確認し、会話・状況の用意・複数講評・音声・サーバーを合わせた検証計画へつなぐ。

回答を受け、最初に共通の1プレイと代表2本を具体化し、同じ形式で残り8本も整理する。代表2本の具体化は初期10本の削減や再選定ではない。複数講評を含む結果例と再挑戦・保存までつないで、初回から次のプレイまでに分かりにくい所や詰まりがないか確認する。

その後は影響の大きい不足だけを聞く。質問のたびに別の重要事項を放置しないよう、上の6範囲を更新する。実装前に全ての数値を確定しようとせず、試遊で決める値には検証方法と判断基準を付ける。重要な判断を反映した定義書をClaudeに再レビューし、指摘の解消・未解消とユーザー判断の要否を改めて確認する。

## 終了を判断する基準

10本それぞれで「何を操作し、何が変わり、どう終わり、どう評価され、どう再挑戦するか」を説明できること。共通画面・記録・入力・失敗復旧・少人数運用がつながり、重大な好みの未確認を仮定で埋めていないこと。残る事項が設計で補える細部、または方法の定まった実装・試遊上の検証であれば、企画ヒアリングを区切る。Claudeの好評や資料作成だけを終了根拠にしない。
