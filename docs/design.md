# 初回デモ設計（2026-11-02）

根拠: ユーザー指定の hero-whisper-codex-handoff.md。初回依頼1〜8を対象とし、実プレイのフィードバック後に9以降へ進む。

確定: 一人用PC/スマホ、共通UI、自由入力、コンテンツ選択→概要→会話→結果→再挑戦、JSON/テキスト出力。全体の正式名・配信・ライセンスは未決。

実装判断: 空フォルダなのでNext.js App Router + React + TypeScript。同一プロセスのメモリーセッションを正本とするローカルデモ。SQLite永続化案は後日の運用段階、静的サイト単独案は秘密鍵を保持できないので採用しない。Sitesワークフローはローカル作業として適用し、ホスティング登録や公開は行わない。

責任分離: `src/game/types.ts` が共通契約、`src/content/registry.ts` が登録一覧、`src/content/hero-whisper/index.ts` が状態・ルール・公開情報・終了判定、`src/server/session.ts` が正本・排他・重複防止、`src/server/ai.ts` がOpenAI/明示モック。共通UIはHeroStateを参照しない。

AIは各ターン1回。許可された行動IDと、行動前の短い台詞（提案/理由/質問回答）だけを返す。行動後の結果文はルール側が生成。スキーマ不正・不可能な行動・API失敗では会話も状態もコミットしない。公開画面には発見済みの情報だけを渡す。

セッション: HttpOnlyの所有者cookie、推測困難なID、revisionによる競合拒否、requestIdによる同一リクエスト再送保証、処理中ロック。1セッション100ターン・TTL2時間・プロセス最大200セッション。再起動で消える。単一Nodeプロセス専用で、複数インスタンス/一般公開には永続DB・アクセス管理が必要。

UI: 深緑と羊皮紙色の読書画面。会話種別を区別、状態と妖精の情報を分ける。入力を下部へ置きIME送信防止・文字数制限・再送時本文保持・返信待ちを表示。未実装の第2コンテンツは表示しない。

未検証: この環境にAPIキーなし。実AIスモークテストのみユーザー設定後に実行する。モックの言い換え対応は限定的でありAI接続とは区別する。
