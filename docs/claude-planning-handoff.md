## 3. 再質問しない確定方針

- 仮題は「AIデア放題！」。正式な名称調査は未実施。
- 子供から大人までが、自由な提案で人物や世界を変え、目的達成・笑える意外な展開・人物AIの講評・再挑戦を楽しむ。
- 一人用、PC・スマホのブラウザー。初期約6人が、それぞれ自宅等から好きな時間に遊ぶ。6人同時プレイや対人マルチを要求されたわけではない。
- 自由選択が中心。基本1プレイ3～5分、内容による長短は許容。時間経過だけによる共通の強制終了は採用していない。
- 初期10本。勇者の耳元／01冷蔵庫の深夜国会／07鏡だけが目撃者／13雨に免許を出す仕事／19音を出せない避難訓練／25怪獣映画の字幕係／30誰も悪くない悪役脚本／31善意100％の掃除ロボ／37句読点の修理工／48オチを先読みする落語星人。44は初期から除外。
- 自由度は比較例の「⑤くらい」。既存物の転用に加え、新しい仕組み・役割・作戦で実際に状況を変えたい。列挙済みの正解だけに閉じない。行動可能と成功保証は分ける。
- ゲーム内への働きかけは言葉のみ。証拠クリック、配置ドラッグ、専用エディターでの直接編集は不採用。資料等は見るために表示でき、選択・送信・保存等の共通UIボタンは使える。
- 文字と音声を初期から用意。音声は端末・ブラウザーの認識→文字確認・修正→送信。以前の有料文字起こしAPI必須案は更新済み。
- 各ゲームに固定の星の難度を設定するA方式。初期は各ゲーム内の難度選択を設けない。星の最大数・値は未決。易しいものは低学年でも一人で遊べ、大人も発想を楽しめる。高難度でも状況の説明は子供が理解できるものにする。
- 達成・未達と総合ランクは別。未達でも発想や過程によって高ランクを狙える。項目別評価と総合ランクを出す。
- 複数の人物が、異なる観点・人格で、実際の経過を踏まえたユーモアある講評を行う。3人は比較用の提案で、確定人数ではない。
- 再挑戦は同じ状況と新しい状況の両方を選べる。新しい状況では事情が毎回変わり、整合した設定・結末を成立させる。プレイ途中の真相のすり替えを認める意味ではない。
- 保存で重視するのは「自分が生んだ面白い展開」。結果画面で保存する／しないを選ぶ。全会話の自動保存や公開共有は決めていない。
- コミカルで親しみやすく、独自性・インパクトを徹底。素材は後から差し替え可能。会話部分だけスクロールし、目的・入力等の重要UIを固定する。
- 追加支払い0。本人の現在の利用枠で全員分を賄いたい。有料API、ホスティングのアップグレード、クレジット購入を既定の解決策にしない。

参考作品はおしゃべりキングの多様な題材と意外性、リズム天国の分かりやすさ・親しみやすさ・独創性。個別のお題やキャラクターを複製する指定ではなく、会話力診断やリズムゲームへ変更する指定でもない。

## 4. 残る詳細定義と、誰が何をするか

| 範囲 | 不足と必要な成果物 | 設計側で進めること／ユーザーに必要な判断 |
| --- | --- | --- |
| 10本の各ゲーム仕様 | 各1本の役割・初期条件・固定事実・補完可能範囲・可変状態・人物の知識・終了／成功／失敗・評価軸・短い一連のプレイ例 | まず全10本を同じ仕様テンプレートで設計する。未採用の数値は提案と表示。題名や収録の再選定を当然に始めない |
| 自由な発想と状態更新 | 新しい仕組みを作用へ翻訳し、資源・因果・固定事実を検証する方式。許容例／拒否例／曖昧な例 | 実装者が方式と代表例を提案・試作。既定の有限actionへ戻すだけでは達成しない。目的を不要にする別解等、体験の境界で判断が変わる場合だけ具体例を示して確認 |
| 採点・ランク | 項目、配点、段階・名称・閾値、最高ランク、未実行案・根拠不足・短手数・途中採点の扱い | 通常達成・創造的未達・短手数・根拠不足の4例を使って設計案を比較。ユーザーに配点を一から考えさせず、体験の差を見せて重要な選択を確認 |
| 人物講評 | コンテンツごとの人物、観点、口調、人数・表示順・長さ・必要なら掛け合い | 人物案と同一ログへの講評例を作る。事実は共有し、解釈と価値観だけを変える。最後の手だけを褒めない。ユーザーの面白さ・言い方の好みを具体例で確認 |
| 画面と例外 | タイトル／一覧／導入／プレイ／結果／記録閲覧の配置、資料表示、待機、誤送信、ヒント、退出、中断復帰、採点失敗 | 画面遷移と復旧の流れを設計し、固定UIをスマホで確認。ヒントと採点の関係、取り返せない操作等の大きい体験判断のみ確認 |
| 記録・利用者 | 何を何件保存するか、保存先・削除・端末間共有・認証・中断保存 | 本人専用か各人の記録を分離するか、端末間利用の重要度等に絞って確認。6人へ所有者のAI認証を配る案や公開共有を既定にしない |
| 難度・対象者・表現 | 星の段階、各ゲームの仮難度、説明・読み支援、怖さ・辛口表現の範囲、試遊での調整 | 子供にも分かる状況の例を作り、大人向けの広がりも確認。必要な年齢・同意条件はサービス側の事実と分ける。星の数だけ決めて完成にしない |
| AI提供・上限 | 追加料金0での提供条件、1プレイ総消費、枠切れ・混雑・切断時の挙動、ホストと永続化 | 下記の実測・照会を引き継ぐ。許容するプレイ回数や枠切れ時の待ち等は、必要な比較案を示して確認。未確認の提供条件をユーザーの好みで解決したことにしない |

全ての不足を追加ヒアリングにしない。専門的な設計で補える部分は具体案として進め、ユーザーの価値判断・許容範囲で結論が変わる重要点に質問を絞る。未決を暗黙の採用へ変えない。

## 5. AI・実装の検証結果

Lunaはユーザーが基準モデルに指定。専用OAuthで本人のPlus枠を使う短い推論1回がローカルで成功した。6人の遠隔プレイを本人1契約で処理する許可とは別。公式フォームへ問い合わせは送信済みだが、受付は承認ではなく、回答期限も個別回答の保証も得ていない。重複申請を自動で送らない。

Gemmaは代替候補として正式採用前に比較。Cloudflare Freeで22リクエスト、21完了・1タイムアウト。推論無効＋JSON指定＋お題別の保護文では12/12がJSONを満たしたが、人物の過去の行動をプレイヤーへ誤帰属する等の問題が残る。基本形式検査の合格をゲーム品質の合格にしない。確認時点の実消費198.34/10,000 neuronsは短い検証全体であり、完成ゲーム1プレイの費用ではない。

測定結果は[Gemma API報告](gemma-api-verification.md)と[機械可読結果](gemma-api-benchmark-results.json)。API検証用トークンはユーザー承認で削除し、ローカルの値も除去済み。資格情報の再作成・追加契約等をこの引き継ぎ文書で許可されたとは扱わない。

現行ゲームはNext.js/Reactの勇者デモ。共通UI・差し替え素材・サーバーの状態管理等はあるが、新規9本、自由な新作戦の反映、採点・人物講評・音声の本番統合は未完。現在のプロセスメモリー上のセッションは、Cloudflareの分散・再起動をまたぐ保存の完成形ではない。

## 6. Claudeへ依頼するレビュー

1. ユーザー確定事項と提案が混ざっていないか。特に音声、固定難度、言葉のみ、未達高ランク、6人・追加支出0。
2. 10本が名前の違う同じ会話にならず、行為・変化・成果・終了が異なっているか。
3. 高い自由度と固定事実・サーバー正本を両立する方式が具体的か。新作戦を受け入れる例と拒否する例を検証できるか。
4. 採点の根拠・人物講評・記録が同じ確定した経過を使い、捏造や評価の矛盾を生まないか。
5. 子供でも状況を理解でき、音声確認・AI待機・結果を含む全体の遊びが気軽か。
6. 誤送信・切断・採点失敗・枠切れ・中断から、どの状態へ戻れるかが定義されているか。
7. AIモデルの品質・使用量・利用条件について、ローカル単発やJSON成功を過大評価していないか。
8. 実装の順序と依存関係が明確か。既存デモを無断で壊す変更、大量実装や公開へ飛躍していないか。

レビューの返却形式は「重要度／根拠の文書箇所／プレイ中に困る具体例／修正案／ユーザー判断が本当に必要か」。単なる不明点の列挙ではなく、設計提案で解けるものと外部確認待ちを区別してほしい。

## 8. ファイルの受け渡し

この資料群は現在のローカル作業フォルダーにあり、多くがGit未追跡。コミット・push済みとは扱わない。同じフォルダーを使うClaude Codeは本書から読める。別環境へ渡す場合は文書一式を渡し、コードの監査・実装も依頼するなら対応するリポジトリも渡す。文書だけのパッケージに現在のコード一式が含まれるとは扱わない。

.env、認証ファイル、個人ログ、ブラウザー状態は受け渡し対象に含めない。古い発想資料を含む場合は、現在の確定方針でないことが分かる状態を保つ。
