# Dialogue Quests（仮称）

自由な対話で目的に働きかける、短編ミッションゲームの初回ローカルデモです。正式タイトルは未決。最初のコンテンツ「勇者の耳元 / 日没までの帰り道」を収録しています。ナビ妖精として勇者リオに質問・助言し、月白草を日没までに村へ届けます。

## 起動

Node.js 22以上とnpmが必要です。検証環境はWindows / Node24。

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev
```

[http://127.0.0.1:3000](http://127.0.0.1:3000) を開いてください。既定は **モック**。決まった表現を判定する動作確認モードで、実AI接続ではありません。「橋を調べて」「包帯で手当て」「川沿いへ」「干し肉を置こう」「上着で覆おう」「草を採ろう」「帰ろう」などを試せます。「リオに任せる」で自主判断の一例を進めます。

## 実AIへの接続

`.env.local` をローカルのエディターで編集してください。キーをチャットへ貼る必要はありません。

```dotenv
AI_PROVIDER=openai
OPENAI_API_KEY=ここに自分のAPIキーを設定
OPENAI_MODEL=gpt-6-luna
```

サーバーを止めて再起動。画面が「OpenAI 接続設定」となります。これは設定表示であり、接続成功の保証ではありません。メッセージを送り、応答とログのmodel/usageを確認して初めて実接続を確認できます。利用権限のある別モデルへOPENAI_MODELを変更できます。構造化出力を使用できるモデルを選んでください。API呼び出しは1ターン1回、25秒タイムアウト、自動API再試行なし。失敗時は状態と会話を更新せず、画面の「再試行」で同じ送信IDを使用します。

モデル資料: [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) / [構造化出力](https://developers.openai.com/api/docs/guides/structured-outputs)。個別アカウントの利用権限・課金状態は未確認です。

キーはサーバーだけが読みます。`NEXT_PUBLIC_`変数、Git、ログへ入れないでください。配信先へ移すときは配信先の環境変数に別途設定します。GitHub Actions SecretsからCodexや配信先へ自動共有される前提はありません。通常CIにAPIキーは不要です。

## 遊び方と記録

一覧→概要→開始→対話→結果→再挑戦／一覧へ戻る。質問は原則時間を消費せず、観察・移動・作業で時間が進みます。行動前の台詞と確定した行動結果を別表示します。AIが未知の行動を出した場合は拒否し、正本を更新しません。

ログはプレイ画面のJSONログ／テキストログから保存できます。バージョン・発言・行動・状態前後・時間・終了理由・モデル・取得できたトークン使用量・応答時間を含みます。ローカル保存先は `play-logs/` を推奨し、Gitから除外しています。個人の発言を含むため、共有する場合は内容を確認してください。APIキー・所有者cookie・非公開思考は含めません。リセット前に必要なログを保存してください。

## 検証

```powershell
npm run lint
npm run typecheck
npm test
npm run build
npm run test:ui
npm run test:playthrough
```

`npm run check` はlint・型・テスト・ビルドを順次実行します。E2Eは既存のMicrosoft Edgeを使うローカル設定です。Edgeのない環境ではPlaywrightのChromiumを導入して設定のchannelを変更してください。`test:playthrough` は起動中のlocalhostに3方針の模擬入力を送り、JSON/テキストをplay-logs/へ保存します（モック専用）。CIは主要テストとビルドを実APIなしで実行します。検証結果と実施範囲は [docs/verification.md](docs/verification.md) に記載します。

## 構成

- `src/game`: コンテンツ非依存の型・画面データ契約。
- `src/content`: 初回コンテンツのルールと登録。追加時はContentDefinitionを実装。
- `src/server`: AI接続、所有者と正本セッション、排他、重複防止。
- `src/components`: 名前・目的・状態項目を定義から読む共通画面。
- `tests/support/signal-content.ts`: 勇者・時間・負傷を持たない内部検証定義。公開一覧へは登録しません。
- `docs/design.md`, `docs/rules.md`, `docs/plan.md`: 設計・整合するルール表・実装計画。

## 既知の制約

- APIキー未設定の環境では実AI検証を実施できません。モックを実AI接続済みとは扱いません。
- サーバー正本は単一Nodeプロセスのメモリー。再起動で消え、有効期限2時間・最大200セッション・所有者ごと20セッション・1セッション100ターン。一般公開や複数インスタンス運用には永続DB・認証・利用制限・費用管理を整える必要があります。
- ブラウザ更新では一覧に戻ります。タブのリセット前やサーバー停止前にログを保存してください。別端末への継続は未対応です。
- 対応行動は初回シナリオに定義した範囲。自由入力はAIがその行動へ解釈します。新しい道具・物理法則・能力を自由生成するゲームではありません。
- 初回コンテンツのみ。実プレイのフィードバックを共通/固有に仕分けて調整し、第2コンテンツはユーザーが次へ進むと判断してから追加します。初回デモとゲーム全体完成は区別します。
- ローカル起動は127.0.0.1に限定。`COOKIE_SECURE=true` はHTTPSの配信先で設定。GitHub PagesはAPIキーを保持するサーバーの代替になりません。
- 一般公開・課金契約・公開範囲変更・mainマージ・ライセンス選択は行っていません。GitHub設定は [docs/repository-setup.md](docs/repository-setup.md) を参照してください。
